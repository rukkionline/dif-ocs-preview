# GitHub-first: источник истины и write-gate

Контракт проекта. Обязателен для любых изменений в этом репозитории.
Машиночитаемая часть: `.source-of-truth.json`.

## 1. Канонический источник

- Канонический репозиторий: `rukkionline/dif-ocs-preview` на GitHub; принятая ветка — `main`.
- `main` — принятая версия. Работа ведётся в отдельной ветке и попадает
  в `main` только через pull request.
- Свежий GitHub `main` важнее любого локального checkout: локальная копия
  может быть устаревшей или грязной.
- Статус источника здесь не подтверждён: `source_recovery_status` и
  `production_evidence` равны `UNVERIFIED`. Неизвестный источник нельзя объявлять
  восстановленным. Отсутствие файла, 404 или пустой ответ API — это не доказательство
  пустоты репозитория и не доказательство отсутствия прав.

## 2. Перед началом работы

1. Прочитать project-local правила этого репозитория: `AGENTS.md`, `.agents/rules.md`,
   `.agents/project.md`, `.agents/current-task.md`, `.agents/context-map.md` и то, на что
   они ссылаются.
2. Получить актуальные метаданные, дерево и содержимое из GitHub, а не из локальной копии.
3. Проверить `git status`. Грязный checkout не затирать, не сбрасывать и не «чинить»
   чужую незакоммиченную работу.

Проектные более строгие правила сохраняются и имеют приоритет над этим документом.

## 3. Перед push

- Показать точный diff того, что уходит (точные пути и содержимое).
- Выполнить secret-scan именно этого diff. Секреты, PII и runtime-файлы (БД, логи,
  выгрузки, `.env`) в Git не попадают.
- Push — только обычный, non-force, в отдельную ветку.

Запрещено: `git add -A` и любые широкие массовые добавления, `push --force` /
`--force-with-lease`, автоматическое удаление веток, файлов и refs.

## 4. Финал каждой задачи

Зафиксировать без сокращений: репозиторий, ветку, commit SHA, изменённые пути,
выполненные тесты и проверки, номер PR.

Pushed SHA проверяется read-after-write: ref перечитывается после записи и сравнивается
с записанным. `accepted` не равен `pushed`: отправленный коммит ещё не принят.
Дизайн- и контент-QA не повышаются в статусе из-за доставки файлов.

## 5. Production

Изменение production выполняется только по approved immutable SHA, с backup и
rollback-планом. Неизвестный или невосстановленный источник в production не выводится.

## 6. Границы этого документа

Это только политика (docs/config). Он не подтверждает сверку исходников, не выполняет
deploy, не публикует и не меняет существующие правила проекта.
